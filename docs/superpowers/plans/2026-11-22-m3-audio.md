# M3 Audiokette: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Das Mikrofon läuft durch RNNoise und ein Gate im AudioWorklet. Es gibt drei Sprechmodi (Push-to-Talk, Sprachaktivierung, Stumm), Opus ist für Sprache abgestimmt, und ein Debug-Panel zeigt Latenz und Verbindungsgüte je Peer.

**Architecture:** `getUserMedia`, dann `AudioContext` (48 kHz), dann ein AudioWorklet. Das Worklet sammelt 480-Sample-Frames, schickt jeden durch RNNoise (liefert Audio und VAD-Wahrscheinlichkeit) und dann durch das Gate. Das Ergebnis geht über `MediaStreamAudioDestinationNode` als **ein** Track an alle Peers. Die Logik steckt in reinen, unter Node testbaren Klassen (`rnnoise.ts`, `gate.ts`, `capture-core.ts`); das Worklet und die Pipeline sind dünne Hüllen darum. Das WASM wird im Hauptthread kompiliert und als `WebAssembly.Module` per `processorOptions` ins Worklet gereicht, weil es dort kein `fetch` gibt.

**Tech Stack:** Web Audio (AudioWorklet), `@shiguredo/rnnoise-wasm@2022.2.0` (nur die `rnnoise.wasm`, Apache-2.0, 150 KB; eigener Mini-Loader statt Emscripten-Glue), Vitest, Playwright mit `--use-file-for-fake-audio-capture`.

**Spec:** `docs/spec.md` (§6 Medien, §10 M3, §11 Tests)

## Global Constraints

- `getUserMedia({ audio: { echoCancellation: true, noiseSuppression: false, autoGainControl: true, channelCount: 1 } })`; bei abgeschalteter Rauschunterdrückung `noiseSuppression: true`.
- RNNoise: 48 kHz, 480-Sample-Frames; Eingabe im 16-Bit-Wertebereich (Float × 32768).
- Gate im Worklet. PTT: offen solange gedrückt, **150 ms** Nachlauf. VAD: öffnen bei VAD > Schwelle (Standard **0,85**, einstellbar), schließen nach **400 ms** unter Schwelle, **200 ms** Vorlauf-Puffer (im Debug-Panel abschaltbar). Stumm: Gate zu. Geschlossen = Nullsamples.
- Opus-fmtp vor `setLocalDescription`: `stereo=0; sprop-stereo=0; useinbandfec=1; usedtx=1; maxaveragebitrate=32000`. `ptime` bleibt 20 ms.
- Empfang: `receiver.jitterBufferTarget = 0`, wo vorhanden.
- Wiedergabe weiter über `<audio>` je Peer; Lautstärke je Peer über `audio.volume`.
- PTT-Taste im Browser: Leertaste außerhalb von Eingabefeldern, nur bei fokussiertem Tab.
- Debug-Panel aus `getStats()`: RTT, Jitter, `jitterBufferDelay`, Paketverlust, Kandidatentyp.
- UI-Texte deutsch, duzen, keine Gedankenstriche. Commits eine Zeile, Deutsch, direkt auf `main`.

## Review Focus

1. **Ausgabepuffer driftet oder wächst unbegrenzt** (Vorlauf, Taktunterschiede): Latenz muss nach jedem Sprechansatz wieder abgebaut werden (Task 2 Test „Rückstand wird in Pausen abgebaut“, Task 3 Test „Obergrenze“).
2. **PTT-Taste bleibt „gedrückt“**, wenn der Tab den Fokus verliert, oder Auto-Repeat erzeugt Flattern (Task 6, Tests in `ptt-keys.test.ts`).
3. **Umschalten der Rauschunterdrückung im Gespräch** darf keine Neuverhandlung auslösen; der gesendete Track bleibt derselbe (Task 4 E2E).
4. **Worklet oder WASM nicht ladbar** (alter Browser, CSP): Beitritt geht trotzdem, mit Rohmikrofon und Hinweis (Task 4).
5. **AudioContext startet „suspended“**: Ohne `resume()` im Klick geht nichts raus (Task 4: `resume()` im Beitritts-Klick, E2E prüft gesendete Pegel).

### Task 2: Gate

**Files:** Create `web/src/audio/gate.ts`, `web/src/audio/gate.test.ts`

**Interfaces:**
- Produces:
  - `type SpeakMode = 'vad' | 'ptt' | 'muted'`
  - `interface GateOptions { pttTailMs: number; vadHoldMs: number; prerollMs: number; threshold: number; preroll: boolean }`, `DEFAULT_GATE: GateOptions = { pttTailMs: 150, vadHoldMs: 400, prerollMs: 200, threshold: 0.85, preroll: true }`
  - `class Gate { constructor(o?: Partial<GateOptions>); mode: SpeakMode; setPressed(b: boolean): void; set(o: Partial<GateOptions>): void; process(frame: Float32Array, vad: number): Float32Array[]; readonly open: boolean; readonly lagFrames: number }`
  - Ein Frame = 10 ms. `process` gibt die auszugebenden Frames zurück: geschlossen genau einen Nullframe, offen den Frame, beim Öffnen im VAD-Modus zuerst die gepufferten Vorlauf-Frames (bis 20) und dann den aktuellen.
  - **Rückstandsabbau:** Solange `lagFrames > 0` und offen, wird ein Frame mit `vad < threshold / 2` (Pause zwischen Wörtern) verworfen statt ausgegeben (`[]`), `lagFrames--`. Beim Schließen wird `lagFrames = 0`.

- [ ] **Step 1: Tests** (Hilfsfunktion `run(gate, vads: number[])` zählt ausgegebene Nicht-Null-Frames):
  - VAD: unter Schwelle bleibt zu (nur Nullframes); ein Frame über Schwelle öffnet; danach 39 Frames unter Schwelle bleibt offen, der 40. schließt (400 ms).
  - VAD mit Vorlauf: Beim Öffnen werden die vorherigen 20 Frames in Originalreihenfolge vor dem aktuellen ausgegeben (21 Frames), `lagFrames === 20`.
  - VAD ohne Vorlauf (`preroll: false`): genau ein Frame beim Öffnen, `lagFrames === 0`.
  - „Rückstand wird in Pausen abgebaut“: offen mit `lagFrames 20`, 20 Frames mit `vad 0,1` → alle verworfen, danach `lagFrames 0`, und das Gate ist dabei nicht geschlossen worden (zusammen mit Haltezeit testen: Haltezeit 400 ms > 200 ms).
  - Schwelle einstellbar: `set({ threshold: 0.5 })` öffnet bei 0,6.
  - PTT: ungedrückt zu, auch bei VAD 1; gedrückt offen unabhängig von VAD; nach Loslassen noch 15 Frames offen (150 ms), der 16. ist Null; erneutes Drücken im Nachlauf hält offen; kein Vorlauf in PTT.
  - Stumm: immer zu; Moduswechsel von offenem VAD nach Stumm schließt sofort.
  - `open` spiegelt den Zustand; ausgegebene Frames sind Kopien (Ändern der Eingabe danach ändert sie nicht).
- [ ] **Step 2:** FAIL. **Step 3:** Implementieren (Ringpuffer aus 20 Frame-Kopien). **Step 4:** grün.

  - Worklet `plaudr-capture`: `processorOptions.module: WebAssembly.Module`; `port.onmessage` → `core.control`; `core.onActivity` → `port.postMessage`; `process()` gibt `true` zurück.

  - `denoise: true` gibt das halbierte, `denoise: false` das Originalsignal aus; VAD wird in beiden Fällen ausgewertet (Gate öffnet).
