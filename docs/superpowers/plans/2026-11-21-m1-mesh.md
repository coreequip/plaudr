# M1: Gerüst und Mesh mit Klartext-Signaling – Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drei Browser-Tabs mit demselben Link hören sich gegenseitig über ein WebRTC-Full-Mesh; Signaling läuft unverschlüsselt über room_ws.

**Architecture:** Statische Web-App (Vite, reines TypeScript). `Signaling` kapselt den room_ws-Client und prüft Absender und Adressat, `Mesh` verwaltet je Gegenüber einen `PeerLink` (eine `RTCPeerConnection` mit Perfect Negotiation). Nachrichtenformat ist schon das aus der Spec (Abschnitt 5), nur ohne Verschlüsselung und Signatur; M2 legt diese als Hülle darum.

**Tech Stack:** Node 26, Vite, TypeScript (strict), Vitest, Playwright (Chromium), room_ws als Git-Submodul (Client `example/roomws.js`, Server für E2E-Tests per `go run`).

**Spec:** `docs/spec.md`

## Global Constraints

- Kein UI-Framework; DOM direkt aus TypeScript.
- room_ws wird nicht kopiert: Submodul `vendor/room_ws`, gepinnt auf `56e1c67`, eingebunden als `"roomws": "file:../vendor/room_ws/example"`.
- Jeder Publish mit `no_echo: true`; History wird nicht angefordert.
- ICE-Kandidaten gebündelt: höchstens ein `ice`-Umschlag pro Peer alle 80 ms.
- Polite-Rolle: die lexikografisch kleinere peerId.
- `|now − ts| ≤ 120 s`, `nonce` nur einmal, `cid` muss zum room_ws-`client_id` des Publish passen.
- Wiedergabe über ein `<audio>`-Element pro Peer, nicht über WebAudio.
- Pro Peer ein DataChannel `ctl` mit `negotiated: true, id: 0` (in M1 ungenutzt).
- Standard-Endpunkte: `wss://live.room.ws`, TURN-Credentials `https://live.room.ws/turn`; per `VITE_ROOMWS_URL` / `VITE_TURN_URL` überschreibbar.
- Commit-Nachrichten: eine Zeile, Deutsch, Aussageform, kein KI-Hinweis.

## Review Focus

1. **room_ws-Reconnect während des Gesprächs** (neue client_id): Audio läuft weiter, keine doppelten Peers. → Task 5 (Unit), Task 7 (E2E).
2. **Mikrofon verweigert oder nicht vorhanden:** Beitritt als reiner Zuhörer statt Fehler. → Task 6, Task 7 (E2E).
3. **Tab wird geschlossen:** die anderen bauen den Peer innerhalb weniger Sekunden ab. → Task 5 (Unit), Task 7 (E2E).
4. **Autoplay-Sperre:** `audio.play()` schlägt fehl → sichtbarer Knopf „Ton aktivieren“ statt Stille. → Task 6.
5. **Zwei Tabs treten gleichzeitig bei** (beide schicken `hello`, beide bieten an): Glare wird durch Perfect Negotiation aufgelöst. → Task 5 (Unit über Fake), Task 7 (E2E, gleichzeitiges Klicken).

### Task 3: Signaling

**Files:**
- Create: `web/src/signaling/types.ts`, `web/src/signaling/signaling.ts`
- Test: `web/src/signaling/signaling.test.ts`

**Interfaces:**
- Consumes: Typen `RoomWS`/`Room` aus Task 1 (nur strukturell, über `DroneLike`).
- Produces (`types.ts`):
  ```ts
  export interface Bodies { hello: {name: string}; offer: {sdp: string}; answer: {sdp: string}; ice: {c: RTCIceCandidateInit[]}; bye: Record<string, never> }
  export type Kind = keyof Bodies
  export interface Payload<K extends Kind = Kind> { kind: K; from: string; to: string; cid: string; ts: number; nonce: string; body: Bodies[K] }
  export interface Envelope { v: 0; p: Payload }   // M2: { v: 1, iv, ct }
  ```
- Produces (`signaling.ts`):
  ```ts
  export interface DroneLike { clientId: string | null; subscribe(room: string): RoomLike; publish(m: {room: string; message: unknown; no_echo?: boolean}): void; close(): void }
  export interface RoomLike { on(ev: string, cb: (...a: any[]) => void): void }
  export class Signaling {
    constructor(o: {drone: DroneLike; roomId: string; selfId: string; now?: () => number})
    send<K extends Kind>(kind: K, to: string, body: Bodies[K]): void
    onReady(cb: (cid: string) => void): void      // bei jedem eigenen `members`-Ereignis, also auch nach Reconnect
    onMessage(cb: (p: Payload) => void): void
    onLeave(cb: (cid: string) => void): void
    close(): void
  }
  ```
- `send` setzt `from = selfId`, `cid = drone.clientId`, `ts = now()`, `nonce` = 16 Zufallsbytes base64url, publiziert `{v: 0, p}` mit `no_echo: true`.

- [ ] **Step 1: Tests schreiben** mit einem `FakeDrone`/`FakeRoom`, der Ereignisse per Hand auslöst und Publishes aufzeichnet:

  - eingehende Nachricht mit `to: 'other'` → `onMessage` nicht aufgerufen; `to: selfId` und `to: '*'` → aufgerufen.
  - `p.cid !== meta.client_id` → verworfen.
  - `ts` 121 s in der Vergangenheit oder Zukunft → verworfen; 119 s → angenommen.
  - dieselbe `nonce` zweimal → zweites Mal verworfen.
  - kein Objekt / `v !== 0` / fehlendes `kind` → verworfen, kein Wurf.
  - `members`-Ereignis → `onReady(drone.clientId)`; zweites `members` (Reconnect) → `onReady` erneut.
  - `member_leave('c9')` → `onLeave('c9')`.

### Task 5: PeerLink und Mesh

**Files:**
- Create: `web/src/mesh/peer-link.ts`, `web/src/mesh/mesh.ts`
- Test: `web/src/mesh/mesh.test.ts`

**Interfaces:**
- Consumes: `Signaling`, `Payload` (Task 3), `IceBatcher` (Task 4).
- Produces (`peer-link.ts`):
  ```ts
  export interface PeerLinkOptions { peerId: string; polite: boolean; iceServers: RTCIceServer[]; localStream: MediaStream | null;
    send: (kind: 'offer' | 'answer' | 'ice', body: Bodies['offer'] | Bodies['answer'] | Bodies['ice']) => void;
    onTrack: (s: MediaStream) => void; onState: (s: RTCPeerConnectionState) => void }
  export interface PeerLinkLike { readonly peerId: string; cid: string; name: string; readonly state: RTCPeerConnectionState; handle(p: Payload): Promise<void>; close(): void }
  export class PeerLink implements PeerLinkLike { constructor(o: PeerLinkOptions); readonly pc: RTCPeerConnection }
  ```
  Perfect Negotiation nach dem MDN-Muster (`makingOffer`, `ignoreOffer`, `setLocalDescription()` ohne Argument). Lokaler Track per `addTrack`; ohne `localStream` ein `addTransceiver('audio', {direction: 'recvonly'})`, damit trotzdem verhandelt wird. `ctl`-Kanal laut Global Constraints. `iceConnectionState === 'failed'` → `pc.restartIce()`; nach dem 3. Fehlschlag `onState('failed')`.
- Produces (`mesh.ts`):
  ```ts
  export interface PeerView { peerId: string; name: string; state: RTCPeerConnectionState }
  export class Mesh {
    constructor(o: { signaling: Signaling; selfId: string; name: string; localStream: MediaStream | null; iceServers: RTCIceServer[];
      createLink?: (o: PeerLinkOptions) => PeerLinkLike; onTrack: (peerId: string, s: MediaStream) => void;
      onPeerGone: (peerId: string) => void; onChange: (peers: PeerView[]) => void })
    start(): void
    peers(): PeerView[]
    leave(): void
  }
  ```
- Regeln:
  - `onReady` → `hello` an `*` mit eigenem Namen.
  - `hello` von unbekannter peerId → Link anlegen (bietet über `negotiationneeded` an); von bekannter → `cid` und `name` aktualisieren, Link behalten.
  - `offer` von unbekannter peerId → Link anlegen, dann `handle`. `answer`/`ice` von unbekannter → ignorieren.
  - `onLeave(cid)` → nur den Link schließen, dessen aktuelle `cid` gleich ist. `bye` → Link schließen.
  - Link meldet `failed`: auf der nicht-polite Seite Link neu anlegen, auf der polite Seite schließen und auf das neue Angebot warten. `closed` → entfernen.
  - Eigene Nachrichten (`from === selfId`) ignorieren.
  - `leave()` → `bye` an `*`, alle Links schließen, `signaling.close()`.
