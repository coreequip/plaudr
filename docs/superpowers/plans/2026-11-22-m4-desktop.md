# M4 Desktop-Client (Tauri 2): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** plaudr als schlanke Desktop-App für macOS und Windows: bündelt den Web-Build, globale PTT-Taste mit Loslassen, Tray-Menü mit Sendeanzeige, Fenster schließen = Tray, `plaudr://`-Links, Autostart, native Dialoge für die Sicherung, Installer aus CI, Updates.

**Architecture:** Die App ist der unveränderte Web-Client in einer Tauri-2-WebView. Rust bleibt dünn: Plugins registrieren, Fenster beim Autostart verborgen lassen, Einzelinstanz. Alles Weitere läuft im Web-Code über die JS-APIs von Tauri. Eine Plattformschicht (`web/src/platform/`) kapselt die Unterschiede: Die Browser-Variante ist das heutige Verhalten. Die Desktop-Variante wird nur in der App per dynamischem `import()` geladen, so wächst das Web-Bundle nicht. Regeln (Tastenkürzel, Tray-Zustand, Deep-Link) stecken in reinen, unter Node testbaren Funktionen.

**Tech Stack:** Tauri 2.12 (`tauri` 2.12.x, `@tauri-apps/cli` 2.12.x), Plugins `global-shortcut`, `deep-link`, `single-instance`, `autostart`, `dialog`, `fs`, `process`, `updater` (je Rust-Crate und JS-Paket 2.x, passende Minor-Versionen), Rust 1.98, Vitest, GitHub Actions mit `tauri-apps/tauri-action`.

**Spec:** `docs/spec.md` §8 Desktop-Client, §7 Bedienung (Einstellungen: Push-to-Talk, Start; Tray-Menü), §11 M4. Mock-Artboards „Einstellungen (Desktop)“ und „Tray-Menü“: https://claude.ai/artifact/G5aLE1kEgFVDQR1VgoeLEL. Größenmessung: `docs/spike-desktop.md`.

## Global Constraints

- Tauri **2.12.x**; jede Abhängigkeit exakt gepinnt (Cargo `=x.y.z`, npm ohne `^`), Version mindestens zwei Wochen alt, JS-Paket und Rust-Crate eines Plugins mit gleicher Minor-Version.
- Die App lädt nie die Live-Seite: `frontendDist` = `../../web/dist`, `devUrl` nur für `tauri dev`.
- Release-Profil: `opt-level = "s"`, `lto = true`, `codegen-units = 1`, `panic = "abort"`, `strip = true`. Ziel: `.app` unter 5 MB, `.exe` unter 5 MB.
- Bezeichner `ws.room.plaudr`, Produktname `plaudr`, Version `0.1.0`. Keine Personennamen in Bundle-Metadaten (`publisher`/`copyright` bleiben leer, bis der Nutzer sie nennt).
- Fenster 400 × 780, mindestens 360 × 600, Titel `plaudr`.
- macOS: `NSMicrophoneUsageDescription` = „plaudr braucht das Mikrofon für Sprachgespräche.“
- Tastenkürzel nur mit mindestens einer Modifikatortaste oder als F13 bis F24; ein globales Kürzel blockiert die Taste systemweit.
- Web-Bundle (Pages) bleibt frei von Tauri-Code im Haupt-Chunk; die Browser-Bedienung ändert sich nicht, alle bestehenden E2E bleiben grün.
- UI-Texte deutsch, duzen, keine Gedankenstriche; Texte aus dem Mock wörtlich.
- `localStorage`-Schlüssel neu: `plaudr.desktop` (`{ pttShortcut: string | null }`), Zugriff in `try/catch`.
- Commits eine Zeile, Deutsch, direkt auf `main`, nach jedem Task. Kein Hinweis auf KI.
- Web-Tasks enden mit `cd web && npx vitest run && npm run build && caffeinate -d -u npm run e2e`; Desktop-Tasks zusätzlich `cd desktop && npm run build` (macOS `.app`) und `cargo clippy` ohne Warnungen.

## Review Focus

1. **PTT-Taste hängt „gedrückt“:** Kommt das Loslassen nie an (Bildschirmsperre, Kürzel neu belegt, Modus gewechselt), sendet das Mikrofon dauerhaft. Abmelden, Moduswechsel und Kürzelwechsel lösen immer `setPressed(false)` aus; doppeltes `Pressed` ist harmlos (Task 3, Tests mit Fake-API).
2. **Kürzel belegt oder ungültig:** Ist das Kürzel von einer anderen App belegt, schlägt die Registrierung fehl. Dann erscheint ein Hinweis, und die gespeicherte Taste bleibt erhalten statt still zu verschwinden (Task 3).
3. **Beenden ohne `bye`:** „plaudr beenden“ und Abmelden des Systems müssen erst `mesh.leave()` abwarten (höchstens 1 s), dann beenden. Sonst warten die anderen die Gnadenfrist ab (Task 4).
4. **Deep-Link während eines Gesprächs oder an eine zweite Instanz:** Der Link landet in der laufenden Instanz. Das Gespräch wird sauber verlassen und der neue Raum betreten. Es entsteht kein zweites Fenster und keine zweite Identität (Task 5, Tests zu `secretFromDeepLink`).
5. **Browser-Build unberührt:** Kein `@tauri-apps`-Import im Haupt-Chunk, `isDesktop()` ist im Browser `false`, E2E grün (Task 2, Build-Prüfung per Skript).
